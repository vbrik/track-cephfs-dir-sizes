# Schema version 5 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `trackdir sample` and `trackdir db summary` run on schema version 5, where a sample's work depends on the tree's live directories and on what changed, never on stored history.

**Architecture:** paths move to a dictionary table (`path`); `dir_state` refers to them by id and carries the previous rstats and a `created` flag; `current_dir_state` becomes a table of live directories maintained by the store transaction. The client copies a sample into a temporary staging table and SQL does the rest under the tree lock. `sample` rows carry their counts and phase times, so the summary no longer sorts history.

**Tech Stack:** Python ≥ 3.12 stdlib; psycopg ≥ 3.2 (optional extra); PostgreSQL ≥ 15; pytest, ruff.

**Spec:** `docs/superpowers/specs/2026-11-11-schema-v5-design.md`, sections 4, 5 and 8, and the migration rule of section 7. This is plan 1 of 3; tree names (plan 2) and the overrun rule (plan 3) are not touched here, so `tree` keeps its version-4 columns.

## Global Constraints

- Read `AGENTS.md`, `AGENTS.md.d/`, `docs/conventions.md` and `docs/terms.md` first.
- Tests: `venv/bin/python -m pytest`. Database tests need `python3 scripts/postgres.py start --ephemeral` and `TRACKDIR_TEST_DSN=$(python3 scripts/postgres.py url --test)`; run every task's tests with it set, or they are skipped.
- `ruff format . && ruff check .` before proposing a commit.
- No branches, never push. A "Propose the commit" step shows the message and waits for the user's go-ahead. Commit bodies state the intention and the design choices (`AGENTS.md.d/GIT-v1.md`).
- The repository is public: no real cluster fsids, host names, IPs or real directory paths in code, tests, docs or commit messages.
- Never write to `/mnt/ceph*`.
- `SCHEMA_VERSION` is 5 from Task 1 on. Tasks 1 and 2 both change the version-5 DDL; there is no migration before production, so re-create any development database after each (`scripts/postgres.py reset`, then `trackdir db init`). Plan 2 changes `tree` again; no production data goes into the database before it lands.
- Table names stay `dir_state` and `current_dir_state`. No views.
- Paths are `bytea`, relative to ROOT; a path is unique only together with its tree.
- Output of `trackdir sample` and `trackdir db summary` does not change in this plan.

## Review Focus

Conditions the spec implies and that are likely to bite; each has a test in the task named.

1. A path deleted and created again must keep its `path_id` and be `created` with NULL `prev_*` (Task 1).
2. Two trees holding the same relative path must not share a `path` row, and a tombstone in one must leave the other's current row alone (Task 1).
3. Two samples stored on one connection, and a sample with nothing to store, must work: the staging table must not outlive its transaction (Task 1).
4. A directory whose previous row was an error has NULL `prev_*` but is not `created`; a non-UTF-8 name (`b"caf\xe9"`) goes through staging unchanged (Task 1).
5. A store that fails after staging (out-of-range value, interrupt during `COPY`, concurrent sample) must leave `path`, `dir_state`, `current_dir_state` and `sample` untouched (Task 1), and a summary of a tree whose ROOT is tombstoned must still report (Task 2).

- [ ] **Step 5: Rewrite `store_sample` around a staging table**

After the existing lock, conflict checks and `sample` insert, in the same transaction:

```sql
CREATE TEMP TABLE trackdir_stage (
    path bytea NOT NULL, ino bigint, mode integer, uid bigint, gid bigint,
    nlink bigint, rctime bigint, rbytes bigint, rfiles bigint, rsubdirs bigint,
    error_stage text, error_code text, deleted boolean NOT NULL
) ON COMMIT DROP;
-- COPY trackdir_stage (STAGE_COLUMNS) FROM STDIN: changed probes, then tombstones
ANALYZE trackdir_stage;  -- autovacuum never analyzes a temporary table

INSERT INTO trackdir.path (tree_id, path)
SELECT %(tree)s, s.path FROM trackdir_stage s
WHERE NOT EXISTS (SELECT FROM trackdir.path p
                  WHERE p.tree_id = %(tree)s AND p.path = s.path);

INSERT INTO trackdir.dir_state (path_id, sample_id, <ROW_COLUMNS>,
                                created, deleted,
                                prev_rbytes, prev_rfiles, prev_rsubdirs)
SELECT p.id, %(sample)s, <s.ROW_COLUMNS>, c.path_id IS NULL, s.deleted,
       c.rbytes, c.rfiles, c.rsubdirs
FROM trackdir_stage s
JOIN trackdir.path p ON p.tree_id = %(tree)s AND p.path = s.path
LEFT JOIN trackdir.current_dir_state c
       ON c.tree_id = %(tree)s AND c.path_id = p.id;

INSERT INTO trackdir.current_dir_state (tree_id, path_id, path, sample_id,
                                        <ROW_COLUMNS>)
SELECT %(tree)s, p.id, s.path, %(sample)s, <s.ROW_COLUMNS>
FROM trackdir_stage s
JOIN trackdir.path p ON p.tree_id = %(tree)s AND p.path = s.path
WHERE NOT s.deleted
ON CONFLICT (tree_id, path_id) DO UPDATE
SET sample_id = EXCLUDED.sample_id, <each ROW_COLUMN = EXCLUDED.it>;

DELETE FROM trackdir.current_dir_state c
USING trackdir_stage s, trackdir.path p
WHERE s.deleted AND p.tree_id = %(tree)s AND p.path = s.path
  AND c.tree_id = %(tree)s AND c.path_id = p.id;
```

The `dir_state` insert must run before the two statements that change `current_dir_state`: it reads the state before the sample. Build the column lists from `ROW_COLUMNS`, as the module does today.

- [ ] **Step 3: Write `scripts/loadtest.py`**

Unlike `scripts/postgres.py` it imports `trackdir`, so it runs with the venv's Python. It creates the schema itself and refuses a database that already has one, so it can never touch real data. It builds a balanced tree of `--dirs` directories to `--depth` (default 4) under placeholder names, stores it as an initial sample, then per sample changes `--changes` random leaves and their ancestors (rbytes and rctime). Every `--burst-every` samples it creates `--burst-dirs` directories under one new parent and deletes each burst `--burst-life` samples later. It builds `SampleDiff` directly; it does not walk or replay. Each sample loads the baseline with `load_baseline`, as `trackdir sample` does, and that time is what it reports. The random generator is seeded (`--seed`, default 0).
